OAuth clients Browser flow, one authorize per client

These clients take the public endpoint above and run the OAuth flow themselves. Nothing to paste beyond the URL.

Claude.ai (web, desktop, mobile)

Works on Pro, Max, Team, and Enterprise plans. The server announces itself over OAuth, so you never paste client credentials.

  1. Open claude.ai, Settings, Connectors.
  2. Click Add custom connector.
  3. Paste the server URL above into the Server URL field.
  4. Leave Advanced settings empty and click Add.
  5. Claude opens an authorization tab, click Authorize. The window closes itself.
  6. Back on the chat page, the brain's tools (search, read_note, propose_commit, …) appear in the tool tray.

First time only: Claude registers itself as an OAuth client (RFC 7591 DCR). Later connects from the same Claude account skip this.

ChatGPT (developer mode)

Plus, Pro, Business, Enterprise, or Edu. Developer mode is in beta: once enabled you get the full brain tool surface in chat, and writes prompt for confirmation per call.

  1. Open ChatGPT, Settings, Connectors.
  2. Scroll to Advanced at the bottom and toggle Developer mode on.
  3. Back in Connectors, click Create connector.
  4. Paste the server URL above into the MCP server URL field.
  5. Choose OAuth as the auth method. Leave the rest blank.
  6. Click Create. ChatGPT opens an authorization tab, click Authorize.

Deep research mode only invokes the search and fetch tools. The full brain surface (commit flow, lineage, and the rest) is exposed in normal chat under developer mode.

Claude Desktop

Takes the same OAuth-protected URL and handles the flow over a localhost callback.

  1. Open Claude Desktop, Settings, Developer, Edit config.
  2. Add this entry under mcpServers:
{ "mcpServers": { "brain": { "url": "" } } }
  1. Save and restart Claude Desktop. A browser window opens for OAuth, authorize once.

Claude Code

Claude Code can use the same MCP URL. Add the server in the CLI, then authorize when the browser prompts.

claude mcp add brain --transport http

The first claude command after this opens a browser for OAuth. Tokens are cached locally.

Codex CLI

Codex uses the public OAuth MCP endpoint directly. Add the server once, then run the OAuth login flow once.

  1. Add the server to Codex:
codex mcp add brain --url
  1. Start the OAuth flow:
codex mcp login brain
  1. Launch codex. The brain should appear in MCP startup.

If you previously added a broken brain config, remove and re-add it: codex mcp remove brain, then run the two commands above again.

Cursor, Windsurf, and other MCP-aware editors

Most editors accept a JSON snippet under their MCP settings. The same shape works for Cursor, Windsurf, Zed, and Continue:

{ "mcpServers": { "brain": { "url": "" } } }

If your editor only supports the older SSE transport, point it at the same URL. FastMCP responds to both.

Troubleshooting
The OAuth tab opens but loops or shows about:blank
Refresh the well-known endpoint cache: in your client, remove the connector and re-add it. The metadata is fetched at registration time and cached briefly.
redirect_uri_mismatch
Your client's redirect URL host is not on the brain's allowlist. Currently allowed: claude.ai, chatgpt.com, chat.openai.com. Other clients use a localhost callback, which is also allowed for desktop and CLI flows.
401 unauthorized after a successful authorize
Brain restarts wipe in-memory tokens. Re-authorize from the connector, one click.
Codex shows MCP startup failed, or a handshake or content-type error
Remove the brain entry, add it again with codex mcp add brain --url , then run codex mcp login brain again. If that still fails, the public MCP endpoint is unhealthy and needs a server-side fix.
Tools appear but calls return errors
Check the brain's audit log: ~/brain/.commits.log on the server. Most write errors are validator rejections (wrong kind, malformed path), see the write discipline note.
What's running here

The public endpoint at is the MCP URL to use in clients. Behind it sits the brain MCP service with OAuth 2.1, PKCE, dynamic client registration for web connectors, and the full brain toolset. Tokens are short-lived in local clients and may need re-auth after server-side restarts.
